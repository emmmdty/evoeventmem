# Spec: Evidence-Anchored Multi-Granularity Memory (EAMG)

> **Status**: Draft
> **Author**: opencode
> **Date**: 2026-08-29
> **Replaces**: ETEC+QEMR pipeline (negative result, EM=0.48 vs vector_rag=0.56)

## 1. Motivation

**Why vector_rag wins**: It retrieves exact raw text chunks. The answer is always in the retrieved text.

**Why event memory loses**: LLM extraction paraphrases raw text into summaries (`content` field). Specific details (names, numbers, dates) are lost. The reader sees only the summary, not the original.

**The gap**: No existing system combines the precision of raw text retrieval with the structure of event memory.

**State-of-the-art reference**: HyMem (2026) achieves the best efficiency-performance balance by using dual-granular storage (summary + raw) with dynamic retrieval scheduling. Mnemis (ACL 2026, 93.9 LoCoMo) uses dual-route retrieval on hierarchical graphs.

## 2. New Method: Evidence-Anchored Multi-Granularity Memory

### 2.1 Core Idea

Instead of extracting paraphrased summaries, extract **evidence-anchored event frames** that preserve the original text:

```
Traditional event extraction:
  Raw: "I've been listening to Summer Vibes on Spotify"
  Extracted: "User listens to music on Spotify"  ← detail lost

EAMG extraction:
  Raw: "I've been listening to Summer Vibes on Spotify"
  Frame: {
    event: "user listens to music on Spotify",     ← structured summary
    evidence: "I've been listening to Summer Vibes on Spotify",  ← EXACT raw text
    spans: [{start: 0, end: 52}],                  ← character offsets
    entities: ["Summer Vibes", "Spotify"],          ← extracted entities
    time: null                                       ← temporal info
  }
```

### 2.2 Architecture

```text
Raw Conversation
  │
  ├── LLM Extraction ──> Event Frames (structured + raw evidence)
  │
  ├── ETEC Consolidation ──> Merged/Superseded Frames
  │
  └── Multi-Granularity Index
      ├── Level 0: Raw Turn Chunks (for detail retrieval)
      ├── Level 1: Event Frames (for structured queries)
      └── Level 2: Session Summaries (for cross-session queries)

Query
  │
  ├── Query Classifier ──> intent (detail / structured / cross-session)
  │
  └── Adaptive Retriever
      ├── detail → Level 0 (raw chunks) + Level 1 (event frames)
      ├── structured → Level 1 (event frames) + Level 2 (summaries)
      └── cross-session → Level 2 (summaries) + Level 1 (event frames)
```

### 2.3 Key Differences from ETEC+QEMR

| Aspect | ETEC+QEMR (old) | EAMG (new) |
|---|---|---|
| Extraction output | Paraphrased summary | Structured frame + raw evidence |
| Raw text storage | Only in evidence_refs.quote (not indexed) | Indexed at Level 0 |
| Retrieval | Single path (QEMR) | Multi-granularity adaptive |
| Detail recall | Poor (abstraction) | Strong (raw text indexed) |
| Temporal tracking | ETEC SUPERSEDE | ETEC SUPERSEDE (preserved) |
| Evidence audit | 100% provenance | 100% provenance (preserved) |

### 2.4 Why This Beats vector_rag

vector_rag only has Level 0 (raw chunks). EAMG has:
- **Level 0**: Same as vector_rag (raw text)
- **Level 1**: Structured event frames with temporal info (vector_rag doesn't have this)
- **Level 2**: Cross-session summaries (vector_rag can't do this)
- **Adaptive routing**: Picks the best level for each query type

On detail queries: EAMG = vector_rag (both use raw text)
On temporal queries: EAMG > vector_rag (events have temporal structure)
On cross-session queries: EAMG > vector_rag (summaries aggregate across sessions)

## 3. Implementation Plan

### Phase 1: Evidence-Anchored Extraction (2 days)

Modify the extraction prompt to produce structured frames instead of paraphrased summaries:

```json
{
  "event": "User listens to Summer Vibes on Spotify",
  "evidence": "I've been listening to Summer Vibes on Spotify",
  "entities": ["Summer Vibes", "Spotify"],
  "fact_slot": "music_preference",
  "fact_value": "Summer Vibes"
}
```

The `evidence` field contains the EXACT raw text (not paraphrased). This is the key change.

### Phase 2: Multi-Granularity Index (2 days)

- Level 0: Index raw turn chunks (existing `materialize_raw_turn_store`)
- Level 1: Index event frames with their raw evidence
- Level 2: Create session summaries from event frames
- All levels share the same embedding space

### Phase 3: Adaptive Retrieval (2 days)

- Query classifier: detail vs structured vs cross-session
- Retriever selects which levels to query
- Merge and deduplicate results
- Budget-aware packing

### Phase 4: Validation (1 day)

- 5-sample smoke test
- 10-sample validation
- 50-sample benchmark
- Compare with vector_rag and ETEC+QEMR baselines

## 6. Research Contribution

**Claim**: "Evidence-anchored multi-granularity memory achieves the accuracy of raw text RAG on detail tasks while outperforming it on temporal and cross-session tasks, through structured event frames that preserve exact evidence text."

**Novelty**: Unlike HyMem (summary + raw) or Mnemis (graphs), EAMG uses evidence-anchored event frames that structurally link extracted events to their source text, enabling both structured and detail retrieval from a unified representation.
